# QA Automation Engineer Technical Assessment

## Overview

This project implements the assessment in Playwright + TypeScript:

- Part A — UI Automation: 3 tests against a publicly accessible shopping website.
- Part B — API Automation: CRUD flow against the public Swagger Petstore REST API.
- Screenshots for the three UI tests are saved under `screenshots/`.
- HTML report is generated by Playwright.

### Chosen systems

**UI:** eBay (`https://www.ebay.com`) — publicly accessible shopping site with category navigation and product search.

**API:** Swagger Petstore (`https://petstore.swagger.io/v2`) — public REST API exposing Pet CRUD operations.

The Petstore Swagger UI documents `POST /pet`, `GET /pet/{petId}`, `PUT /pet`, and `DELETE /pet/{petId}` operations.

## Prerequisites

- Node.js 18+
- npm

## Setup

```bash
npm init playwright@latest
npx playwright --version
```

## Run

Run everything:

```powershell
npx playwright test
```

Run UI only:

```powershell
npx playwright test tests/ui
```

Run API only:

```powershell
npx playwright test tests/api
```

Run with browser visible:

```powershell
npx playwright test --project=chromium --headed
```

Open the HTML report:

```powershell
npx playwright show-report
```

## Assessment mapping

### UI Automation

1. `home-page.spec.ts`
   - Opens the home page.
   - Verifies key navigation/search elements.
   - Captures a full-page screenshot.

2. `category-navigation.spec.ts`
   - Uses the home-page navigation to open Electronics.
   - Verifies the destination page.
   - Captures a screenshot.

3. `search.spec.ts`
   - Searches for a dynamically selected product term.
   - Verifies the results page and search term.
   - Captures a screenshot.

### API Automation

`pet-crud.spec.ts` implements the required CRUD sequence:

1. Create — POST `/pet`
2. Read — GET `/pet/{id}`
3. Update — PUT `/pet`
4. Delete — DELETE `/pet/{id}`
5. Confirm deletion — GET `/pet/{id}` and verify an appropriate not-found/error response.

The created pet name is dynamically generated so the test does not rely on a hardcoded resource name.

## Notes

- Public websites can change their DOM or introduce anti-bot behavior. The UI selectors are intentionally based on accessible labels/text where possible.
- If eBay blocks automation in your environment, change `UI_BASE_URL` to another public shopping site and update the three UI tests accordingly.
- The assessment asks for screenshots in a `verification/` directory. The tests create this directory automatically.
